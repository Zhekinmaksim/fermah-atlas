What Fermah is

One engine underneath.

Every smart contract ever written is reactive: it reads a condition and emits a value, then waits for a human, a server or a cron job to do the next thing. Fermah Kernel — which the team calls the Protocol Agency Engine — turns “if this verifiable thing is true, do that” into an on-chain primitive: observe the event, run the logic in a sandboxed container, settle the verified result back on-chain. Two products run on it in production today. Froben is the universal proof market, live on mainnet, with ZKsync Era and Abstract Chain named as paying customers. Flashcast Social turns any topic into a prediction market in a second and resolves it automatically, with no committee and no dispute window. The current Fermah docs also list Fermah Pay as a USDC payments layer and Marina as privacy-preserving data infrastructure, both separately from Froben and Flashcast.

Read it at fermah.xyz and docs.fermah.xyz.

Inside Kernel

From condition to continuation.

From request to a usable proof.

An illustrative Froben workflow, based on Fermah's product and execution descriptions. Not live network telemetry.

  1. 01

    Initiate

    A protocol submits a proof request and its requirements.

  2. 02

    Prepare

    The workflow obtains the inputs needed for that proof.

  3. 03

    Route

    The request is allocated to a compatible prover.

  4. 04

    Execute

    The prover generates the proof; the workflow verifies the result.

  5. 05

    Settle

    The verified result is returned for onchain consumption.

  6. 06

    Continue

    A consuming protocol can use that result as input to its next action.

From a condition to an outcome.

An illustrative Flashcast workflow. The condition and source rules are defined before resolution; this is not a live market or a betting interface.

  1. 01

    Initiate

    A market reaches its defined condition or deadline.

  2. 02

    Prepare

    The workflow fetches the sources specified by the market.

  3. 03

    Route

    The required resolution work is coordinated for execution.

  4. 04

    Execute

    The resolution logic evaluates the evidence against the condition.

  5. 05

    Settle

    The resulting outcome is delivered onchain for settlement.

  6. 06

    Continue

    The result can be consumed by a subsequent protocol action.

Consumption horizon

Where will the result be used?

Fermah describes identical computation taking different execution paths as its output serves different consumers. Its October 24 post calls this the consumption horizon.

Local consumption
Native
Next action
TEE
Future sequences
ZK

This is Fermah's stated routing principle, drawn from its discussion of 2.8M+ production proofs. It is not a universal routing rule, a deployment command or a latency guarantee; the post does not specify detailed security assumptions or selection thresholds.
