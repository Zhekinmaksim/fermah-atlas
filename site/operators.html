Running a prover node

Start with the assigned profile.

A Seeker submits a Proof Request, the Matchmaker allocates it, and a prover node generates the proof. Onboarding is permissioned: submit your Mainnet Ethereum public address to Fermah for whitelisting and obtain the assigned prover-node name before installation.

  1. Prepare the server

    Use a supported OS, compatible NVIDIA drivers and CUDA toolkit, Docker and NVIDIA Container Toolkit.

  2. Configure the identity

    Install the prover binary, use the assigned configuration and create the machine secret. Keep private keys and secrets on your machine.

  3. Register, then start

    Configure Ethereum Mainnet RPC, register the node, set up telemetry and start it. The --el registration flag applies to an already-registered EigenLayer operator participating with the same operator identity key.

Multiple GPUs and remaining setup questions

The Multi-GPU guide describes one prover-node instance/container per GPU, separate Fermah home directories, unique machine secrets, independent registration and explicit GPU pinning.

Its examples mount /var/run/docker.sock and use root systemd services. The guide does not explain how those examples relate to the rootless prover-container requirement; confirm the container context for your setup.

The checked guides do not establish a universal stake minimum, bandwidth minimum or uptime SLA. This does not establish that no such conditions exist.
